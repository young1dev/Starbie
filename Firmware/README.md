# Starbie Firmware

The firmware for **Starbie**, a motion-controlled digital pet built around the Seeed XIAO ESP32-C3.

Built with PlatformIO and the Arduino framework, the firmware controls the OLED display, processes motion input, and adds vibration feedback to the pet's interactions.

## Features

- **Virtual pet display:** Displays an animated, two-eye character on an OLED screen.
- **Motion interaction:** Uses the MPU6050 to detect movement and enable motion-based interactions.
- **Radial menu:** Provides a tilt-controlled menu for navigating the pet's actions.
- **Pet stats:** Includes a stats screen displaying the pet's internal values.
- **Shake reaction:** Responds to shaking the device.
- **Vibration feedback:** Activates a vibration motor during the shake interaction.

## Development Environment

- **Microcontroller:** Seeed XIAO ESP32-C3
- **Framework:** Arduino
- **Build system:** PlatformIO
- **Language:** C++

## Getting Started

### Requirements

- Visual Studio Code
- PlatformIO IDE extension
- Seeed XIAO ESP32-C3
- The compatible display and sensors required by the firmware

### Hardware Configuration

Sensor and peripheral pin assignments are defined in `src/main.cpp`. You can edit these definitions to match your wiring or customize the pinout for your setup. Make sure the selected GPIO pins are compatible with the XIAO ESP32-C3.

### Build and Upload

1. Install Visual Studio Code and the PlatformIO IDE extension.
2. Open the `Firmware/` directory as a PlatformIO project.
3. Allow PlatformIO to install the configured platform and libraries.
4. Connect the Seeed XIAO ESP32-C3 to your computer over USB.
5. Run PlatformIO's **Build** command to compile the firmware.
6. Once the required hardware is available, use **Upload** to flash the firmware to the board.

## Controls

- **Button 1:** Opens the radial menu. Tilt the device toward an action to select its sector, then press Button 1 again to confirm.
- **Button 2:** Shows or hides the stats screen without changing the pet.
- **Shake:** Triggers the pet's shake interaction and can wake it from a nap early.

The pet normally appears as a wandering, 32 × 32, one-bit sprite.

- **NAP:** Keeps the pet still while drifting `z` characters indicate sleep.
- **PLAY:** Moves the pet through two fast laps, accompanied by hearts.
- **PET:** Sends hearts upward.
- **Other actions:** Trigger a small side-to-side shake followed by a jump.

Pet statistics are displayed on the stats screen.

The final word in each menu line determines the visual reaction: `NAP_REACTION`, `JUMP_REACTION`, `HEART_REACTION`, or `RUN_REACTION`.

## Vibration Feedback

Starbie extends the original pet interaction with a vibration motor that provides physical feedback when the device is shaken.

The firmware controls the motor through a GPIO connected to an external MOSFET driver circuit. A timed pulse activates the motor and switches it off automatically.

The motor must be connected through the appropriate driver circuit rather than directly to an ESP32-C3 GPIO. Refer to the main project README and KiCad schematic for the hardware design.

## Customizing the Pet Sprite

The default pet artwork is a 32 × 32 black-and-white bitmap named `PET_SPRITE` in `src/main.cpp`.

To create a custom sprite:

1. Create a high-contrast black-and-white image at your preferred dimensions. Keep the width divisible by 8; 32 × 32 pixels is a good starting point.
2. Open [image2cpp](https://javl.github.io/image2cpp/), a browser-based tool that converts images into byte arrays for embedded projects.
3. Select **Horizontal 1 bit per pixel** output for compatibility with the Adafruit GFX `drawBitmap()` format.
4. If the preview appears inverted, try the invert option in image2cpp.
5. Replace the existing `PET_SPRITE` bitmap definition in `src/main.cpp` with the generated byte array.
6. Update `PET_SPRITE_WIDTH` and `PET_SPRITE_HEIGHT` to match your image dimensions.

Keep the sprite definition and its dimensions consistent so the firmware renders the image correctly.

Build the firmware with PlatformIO after making changes. Test it on the target hardware when available.
